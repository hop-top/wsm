Getting Started with
Squad Topologies

Organizing autonomous agent units for fast flow
and minimal context load
1 Identify what kind of squads you currently have
🗺️
Map your agents to common squad types
Stream-aligned, Enabling, Complicated Subsystem, Platform, Orchestrator, Sentinel
🔍
Identify which squad types to avoid or redesign
Look for undeclared orchestrators and squads without context boundaries
2 Fit agent clusters to the fundamental squad types
Stream-Aligned
Owns a domain pipeline end-to-end. Self-sufficient unit of work. Primary value producer.
Enabling
Temporary attachment. Closes a capability gap in a stream squad, then exits. Must have a defined exit condition.
Complicated Subsystem
Hard problem behind a clean interface. No squad should replicate this. Exposed strictly as a service.
Platform
Shared substrate: tool registry, memory, prompt versioning, cost telemetry. Self-service golden path.
Orchestrator
Decomposes goals, routes tasks, synthesizes results across squads. No domain ownership. Explicitly declared.
Sentinel
Continuous observation: monitors squads for drift, quality degradation, cost overruns, safety boundaries.
3 Limit the context load for each squad using…
📦
Keep the squad context-bounded
A squad's context window should be dominated by domain knowledge, not coordination overhead
🎯
Align the squad to one domain on an ongoing basis
Avoid squads that span multiple domains — they accumulate context debt fast
✂️
Break monoliths at natural context fracture planes
🧱
Provide a platform squad as the underlying substrate
⚖️
Limit the scope of the subsystem each squad interacts with
4 Use the "Inverse Conway" approach to help to:
🔄
Drive agent communication patterns that align to value flow
Design the topology first. The agent communication architecture follows.
🌱
Produce agent architectures that are sustainable by the system
Topologies that evolve deliberately instead of accreting communication debt
🧭
Constrain (and align) the interaction space for each squad pair
Declare interaction mode explicitly. Don't let it emerge from implementation convenience.
5 Identify as-is and to-be squad interaction modes
⚡
X-as-a-Service
Stable, versioned, self-service. No coordination. Default target state for all squad pairs. Producer doesn't know consumers.
🤝
Collaboration
Bidirectional, time-boxed. For discovering unknowns together. Must graduate to X-as-a-Service. Failure mode: permanent entanglement.
🎓
Facilitating
Enabling squad teaches a stream squad, then exits. Exit condition must be declared before attachment begins.
📡
Supervised Delegation
Orchestrator hands a task to a squad but retains oversight authority — can interrupt, redirect, or reclaim mid-flight.
6 Explicitly guide (and limit) inter-squad collaboration to
🔬
Inform and guide the development of Platform and Complicated Subsystem interfaces
Collaboration surfaces the right contract. Then freeze it.
⚡
Drive rapid discovery at points of technological, domain, or context-boundary learning
Time-box it. Define graduation criteria before you start.
7 Evolve squad structures explicitly over time
🔧
Adopt new tools and models as platform capabilities
📐
Improve interaction contracts based on measured load
🚫
Avoid topologies that generate context entanglement
8 Use squad interactions for system sensing
🛡️
Use the Sentinel squad as a high-signal layer for rapid course correction
Drift, cost overruns, and safety boundaries — detected before they cascade
🔁
Use interaction mode patterns to course-correct topology early and often
Collaboration that persists is a signal. Facilitating that never exits is a signal.

in a Nutshell

Why agent systems need explicit topology design
Do you find that your agent system…
🚧 Flow of value is blocked by coordination overhead?
🧠 Context windows are dominated by coordination, not domain knowledge?
⚠️ Too many surprises from emergent agent communication patterns?
🌀 Squad boundaries are unclear or constantly renegotiated?
↓
…which is leading to…
🏗️ Topology that fights Conway's Law instead of using it
🪢 Squads pulled in many directions, context-entangled
💸 Painful context re-engineering every time a squad changes
🔇 Drift and degradation going undetected until it cascades
↓
If the answer is yes? You can change things by…
🎯 Taking a squad-first approach — design topology before architecture
🔀 Using the Inverse Conway Maneuver to define agent communication patterns
📋 Defining Squad APIs — explicit interaction mode contracts between every squad pair
🧩 Utilizing the 6 fundamental squad topologies with declared roles and boundaries
