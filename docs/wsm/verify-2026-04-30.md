## Findings

### Finding 1 (CRITICAL): leftover `vendor/` dir blocks `go build ./...`

- expected: `CGO_ENABLED=1 go build -buildvcs=false ./...` succeeds
- actual: fails with `cannot find module providing package
  hop.top/kit/go/core/config: import lookup disabled by -mod=vendor` until
  `vendor/` is deleted (or `-mod=mod` is forced). Since Go auto-enables
  vendor mode when go.mod >=1.14 and vendor/ is present, the spec'd build
  command fails on a fresh checkout where vendor was generated for the
  charmui path (`go mod vendor -modfile=go.charm.mod`). Test suite
  cascades: 21 e2e tests in `tests/e2e/` fail because they shell out to
  `go build` without `-mod=mod`.
- evidence:
  ```
  pkg/config/config.go:17:2: cannot find module providing package
    hop.top/kit/go/core/config: import lookup disabled by -mod=vendor
    (Go version in go.mod is at least 1.14 and vendor directory exists.)
  ```
  After `trash vendor/`, build clean and 412 tests pass.
- root cause: `vendor/` is in `.gitignore` but Makefile target
  `build-charm` uses `-modfile=go.charm.mod` which encourages vendor
  presence. No cleanup after charm build.
- suggested follow-up: clean vendor/ at end of charm targets, or add
  `-mod=mod` to default go invocations, or migrate away from vendor for
  charm path entirely.

### Finding 2 (MEDIUM): Makefile retains charmui targets and guard

- expected: charmui-tagged build path removed (T-0086 migrated bubbletea
  v1->v2; charm build path is dead code).
- actual: Makefile still defines `build-charm`, `test-e2e-charm`,
  `verify-no-ui-leak` targets and references `go.charm.mod`.
- evidence (Makefile:23-52):
  ```
  build-charm:
    GOCACHE=...go build -tags charmui -modfile=go.charm.mod -o bin/wsm-charm ./cmd/wsm
  test-e2e-charm:
    GOCACHE=...go test -tags charmui -modfile=go.charm.mod ./tests/e2e -run 'TestTUI|...'
  verify-no-ui-leak:
    ...grep -q 'charmbracelet' && (echo 'error: charmbracelet leaked' && exit 1)
  ```
- suggested follow-up: drop `build-charm`, `test-e2e-charm`,
  `verify-no-ui-leak`, `go.charm.mod`, and the `charmui` build tag.

### Finding 3 (MEDIUM): CI workflow still runs charmui build + e2e

- expected: no charmui references in `.github/workflows/`.
- actual: ci.yml steps "Build charmui path" + "E2E (charm build)" + the
  earlier "Verify pkg/* UI dependency boundary" step still run on every
  push/PR.
- evidence (.github/workflows/ci.yml:26-33):
  ```
  - name: Verify pkg/* UI dependency boundary
    run: make verify-no-ui-leak
  - name: Build charmui path
    run: make build-charm
  - name: E2E (charm build)
    run: make test-e2e-charm
  ```
- suggested follow-up: remove these 3 steps from ci.yml in lockstep with
  Finding 2.

### Finding 4 (MINOR): unknown subcommand `remove` returns exit 0

- expected: `wsm workspace remove anything` errors with non-zero exit.
- actual: prints parent's help and exits 0. Same for `space remove` and
  `snapshot remove`. Cobra's default behavior when an unknown
  subcommand is given falls through to help instead of erroring.
- evidence:
  ```
  $ wsm workspace remove anything; echo $?
  <prints workspace help>
  0
  ```
- impact: scripts that previously caught `remove`-vs-`delete` rename
  errors will now silently no-op.
- suggested follow-up: enable cobra's `Args: cobra.NoArgs` on group
  commands or add an explicit `unknown command` error.

### Finding 5 (MINOR, RESOLVED in T-0097): canonical event-add syntax recorded

- expected: spec block in section 10 reproduces happy-path with valid
  syntax and a real event type.
- history: original T-0089 spec used `wsm event add e2e-smoke
  message.added '{...}'` (3 positional args + invented type), which
  returned `accepts 2 arg(s), received 3`. Real shape is `wsm event
  add <workspace> <type> [--data <json>]`; valid type prefixes are
  `workspace.*`, `interaction.*`, `mutation.*`, `topology.*`,
  `checkpoint.*`, `device.*` (see `pkg/model/types.go:33-53`).
- canonical happy-path command (verified exit 0, prints
  `Recorded interaction.message seq=N id=...`):
  ```
  wsm event add <ws> interaction.message \
    --data '{"role":"user","content":"hi"}'
  ```
- T-0097 update: §10 row now records the corrected command. Future
  runbooks MUST use this shape.
